# Meridian decisions — change set 1 (17 November 2026)

## Session diagnosis and fix

Inspection found that Logo already used Next Link, always targeting `/`. The landing page always rendered guest navigation, and neither `/` nor `/sign-in` restored/redirected authenticated sessions. Proxy's refresh matcher excluded both routes and `/start`. There was no signOut caller in that navigation path, and server auth already persisted tokens in cookies. The symptom was guest-page navigation, not an intentional logout. The production browser test now proves sign-in → logo → reload retains the session, and authenticated root/sign-in visits redirect to `/projects`.

AuthProvider bootstraps from a no-store same-origin session endpoint and exposes loading. Logo waits for session resolution through this state; server guards await the SDK's cookie-backed getCurrentUser before making a decision. Protected API authorization remains server-side. Only the explicit Sign out button calls the sign-out endpoint, whose handler is the sole SDK signOut caller. No OAuth UI or provider is added.

## Neutral exploration and manual decisions

`/projects` replaces `/feed`. Newest first is default; oldest and open-role count are the only alternatives. Filters and cursor keys never reference vectors. Verified members can explore and apply before finishing onboarding; their missing profile row is initialized transactionally on apply. Leading still requires the profile setup. An absent or incompatible embedding produces null cosine rather than hiding a project or blocking an application. Same-provider/version comparison remains mandatory. Role cosine uses the role vector; card/overall cosine uses the project vector.

New migrations remove the personalized RPC, match settings table, approval bands, weighted/composite scores and project auto-approval column. Historical cosine and skill snapshots remain. Existing approved memberships are retained. Applications always start pending; own projects, duplicate role applications, and closed projects are rejected. Invalid IDs/roles and authentication failures remain ordinary integrity checks. Whole-project applications are allowed even when roles exist. Duplicate historical applications stay duplicates, including withdrawn ones, as requested. No cosine controls invitations. Approval/acceptance retains project-row locks and both role/overall capacity limits. Team size includes the lead.

## Domains, taxonomy and canonical text

The seed contains 2,108 skills across ten fields and 83 domains. It combines existing tools and aliases, concrete engineering tools, and independently learnable domain competencies (for example FPGA timing analysis). These are a starting educational taxonomy, not an accreditation standard. Existing canonical names/slugs and IDs remain stable. An existing AWS/Amazon Web Services alias collision was removed without renaming either canonical skill. Upserts preserve profile_skills references. Pending custom skills remain unverified and may have no primary field until reviewed.

Domains are selected before skills. Browse follows field/domain; aliases participate in search; skill and vector windows are virtualized. Templates are editable suggestions, never requirements enforced on members. Domain names are stored in canonical sorted arrays and normalized many-to-many joins. Empty domain arrays on old profiles/projects are preserved until their owners choose them, rather than inferring personal interests.

Domain-aware canonical format changes bump both providers. The final frozen expanded taxonomy corpus bumps hashed to domains-tfidf-v4; MiniLM is domains-minilm-751bff37-q8-v2. Reembed-all migrates saves atomically and skips identical hashes. Twenty-six labelled calibration pairs per provider include FPGA, power and mechanical examples. Cosine is shown raw, with no gauge or thresholds: a gauge is optional and would add unnecessary interpretation to these small illustrative fixtures.

## Trace, reproducibility and privacy

Generation stores canonical text/hash, actual tokenizer IDs/tokens (hash IDs for fallback), sequence/truncation metadata, pre/post norms, vector statistics, elapsed time and timestamp. Unchanged saves do not touch a trace or its generation timestamp. Reads never invoke embed. Trace-only backfill reconstructs canonical text with the matching version, regenerates in memory, checks source hash and max vector difference <=1e-6, and updates only missing traces. Legacy versions must migrate first; the script never invents legacy tokenizer metadata. The optional interactive recompute button is omitted to keep generation out of read flows; the backfill and verify-model scripts supply reproducibility checks.

Profile vectors and traces are owner-only in RLS and the server endpoint. Projects/roles are readable by verified signed-in users. Leads see applicant cosine snapshots, skill overlap and a formula explanation; they never receive applicant raw vectors or dimension tables. A member's similarity explanation reads their own vector plus the public project/role vector. Applications show their historical cosine beside calculations from current vectors, explicitly labelled; subsequent edits can make them differ.

The 384-row multiplication table displays raw coordinate products and their running dot product. The final cosine divides by both stored norms; this distinction avoids claiming floating-point vectors have exactly unit length. JSON exports carry actual stored numbers. Trace and vector presentations are text/HTML/SVG with keyboard-accessible scrolling and inherited dark theme.

## Offline model deployment

Source: https://huggingface.co/Xenova/all-MiniLM-L6-v2, Apache-2.0, revision 751bff37182d3f1213fa05d7196b954e230abad9. Exactly five files are downloaded: quantized ONNX plus config/tokenizer/tokenizer-config/special-token JSON. MANIFEST records SHA-256 for each; LFS SHA is checked against Hub metadata and subsequent builds verify all bytes. Files are git-ignored and omitted from source upload (the upload rejected binary-inclusive sources with HTTP 413); prebuild downloads them on the build host. Next output tracing includes model assets. Runtime remote loading is unconditionally false, local path is absolute, and q8 is selected. Native Windows ONNX inference was verified. Missing/corrupt files or model-load failure select hashed fallback with a warning and distinct provider identity. No remote inference service is provisioned.

InsForge Sites remains on the hashed default to avoid model cold-start dependence. Health reports the active provider, revision and file/checksum state. Switching providers requires running reembed-all; incompatible historical vectors are never compared during transition. The model's download requires build network; runtime inference never contacts Hugging Face.

The portal supplies aria-modal dialog semantics, keyboard tab wrapping, Escape, backdrop and close controls. Background app surfaces are inert while open; body scroll and scrollbar padding are restored on close/unmount. Desktop width is min(1100px,78vw), tablet 90vw, mobile 100vw; expansion uses full width. Header/tabs remain outside the internal scroll container. A mutation-observed heading list provides a collapsible/wide table of contents and scroll spy. No schema/RLS changes are needed. GET /api/embeddings/me always selects the session owner's row, ignoring supplied identity query parameters. GET /api/projects/[id]/embedding?role=<id> validates role membership and returns only the selected public project/role embedding. SHOW_COSINE_BADGE is now a server-runtime flag, default true, passed through a lightweight client context. Setting it to false removes only the badge; the FAB and panel remain available. This requires restarting/redeploying the server, not a different model or embedding migration.

Browser tests cover removal/404, no heavy requests or explainer chunk on normal pages, FAB location, per-tab cache/fetch, keyboard/backdrop/X/Back, refresh, focus/scroll, expand/mobile/layer tokens, owner endpoint privacy, snapshot/current display, 384-row parity, empty state and a second production instance with badges disabled. Tests reuse ignored authenticated browser state between cases to avoid repeatedly consuming auth rate limits. Existing RLS/scoring integration and unit checks remain in place.


## Change set 4 — staged MiniLM rollout

Selection is explicit: only minilm/hashed are accepted, configuration errors fail startup, and MiniLM load/inference errors return 503 without selecting or writing hashed vectors. Saves generate all vectors before their atomic RPC, preserving existing profile/project data on failure. The process caches selection/error metadata. Public health reports the actual provider identity and live Transformers.js environment; detailed health uses X-Health-Token and caches in-memory smoke inference for 60 seconds.

The CLI has no preview target option, so host validation uses a production diagnostic deployment with embedding writes paused via EMBEDDING_WRITES_PAUSED=true. Read-only matching remains available; existing vectors are not migrated before the host smoke check. This short maintenance gate avoids accidental mixed-provider writes during rollout. No Plan B service is provisioned unless the host test fails.

The deploy script does not set the production provider from local values. It compares local configuration against live production health before and after deploy and fails on disagreement. The production deployment setting is authoritative; the CLI only exposes encrypted metadata, so live runtime comparison is used instead of pretending the CLI can decrypt it. Initial provider transition is configured explicitly as part of this authorized rollout.

Host validation passed before vector migration. The first deployment failed because NFT included onnxruntime_binding.node without its dlopen dependency libonnxruntime.so.1. Moving native loading out of startup made the error observable as a 503. The protected endpoint confirmed Node v26.13.1 / Linux x64. Adding that platform's libraries enabled inference; the probe returned 384 non-zero dimensions, norm 1.0, related cosine 0.686601208 versus unrelated 0.118503051. Transformers.js 3.8.1 and onnxruntime-node 1.21.0 are loaded on the deployed host. There is no need for Plan B.

A broad native-library include unexpectedly pulled in the host-installed CUDA/TensorRT providers. That probe's deduplicated /var/task footprint was 450,500,195 bytes. CPU-only explicit includes and exclusions reduced the v3 deployment to 112,285,307 bytes (107.08 MiB), including 44,319,808 native bytes. These measurements are the actual files visible in the deployed function, not the source-upload size or an inaccessible official archive/layer metric. Vercel's current standard limit is 250 MB uncompressed (https://vercel.com/docs/functions/limitations). The final host smoke test passed again after exclusions. Keep both libonnxruntime.so.1 and its versioned CPU library because the installed artifact contains both names; no GPU execution provider is used.

Canonical v3 omits all empty sections, normalizes and sorts names, and retains full role details in project text. The read-only pre-migration audit found 0/42 profiles, 0/26 projects and 0/40 roles over 256 tokens. Existing maxima were 64/185/59; v3 maxima are 48/167/52, respectively. Project role-title-only candidates maxed at 80 but were unnecessary because project truncation was 0%, below the 10% trigger. The bundled tokenizer JSON advertises 512 positions; the app explicitly sets tokenizer.model_max_length=256 before inference, matching the upstream sentence-transformer default. The trace uses the same tokenizer and cap. Versions are domains-minilm-751bff37-q8-v3 and domains-tfidf-v5; hashed also bumps because canonical semantics changed. Existing domains remain empty where users never selected any. No migration invents domain choices.

New project/onboarding validation uses a min(1) domain schema on client and server, with new roles inheriting the project choice. A legacy completed profile/project can still save with empty domains; new roles on a legacy project must choose/inherit at least one. Suggestions query real skill_domains links, count unique skill hits and break ties by domain name. Confirm updates form state only; Save is required. The arrays are authoritative and one secured database trigger updates join rows in the same transaction. Existing save RPCs no longer duplicate that responsibility. The added migration leaves all earlier migrations unchanged. The invariant query and integration checks compare the arrays against the joins.

The active provider chip is separate from the stored model label. Regeneration controls call authenticated, same-origin, rate-limited server saves using persisted inputs and CAS revisions, so unchanged hashes still skip inference. Raw profile vectors remain owner-only. Old application/invitation cosine snapshots retain their old model/version and are displayed as snapshots rather than being masked by the current provider's identity. Current null or obsolete-identity comparisons display Embedding is being updated. Viewing the panel performs no inference; only its explicit regeneration action does.

Local Next/Turbopack repeatedly failed to create its CSS worker, even outside the sandbox. npm run build now uses supported webpack mode, which passes. The hosted v3 CPU-only build and live smoke also pass in this mode. An attempted local server start with writes enabled before the migration was rejected by automatic review; it was replaced by a server retaining the write pause.
